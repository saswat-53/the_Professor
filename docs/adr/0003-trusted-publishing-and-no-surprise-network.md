# Publish with trusted publishing; the only network call is your endpoint

Releases go out from GitHub Actions using npm trusted publishing (OIDC), so there is no long-lived npm token and provenance is attached automatically. The tool has no telemetry, no analytics and no update check, and makes no network call except to the endpoint the user configured. A CI test checks that for Node-level connections (socket connects, DNS lookups, UDP) and for spawned commands (git, plus the platform's clipboard tool — `pbpaste`, `wl-paste` or `xclip` — for `--clip` runs only) during the covered runs: first run with no config, `--dry-run`, `--help`/`--version`, a failing request, a refused connection, a successful stream, `file:line`, piped-input, clipboard and config-file runs. It does not see a spawned external binary beyond the command name, HTTP/2 or code that connects after the process exits, so the promise is tested, not proven. Dependencies are scanned separately for known telemetry or update-check packages. The OS keychain (`@napi-rs/keyring`, optional) is a local store; on Linux it talks to the Secret Service over D-Bus on this machine, which the CI test cannot see, so that is part of what is promised rather than proven. The README states that the configured endpoint receives the user's code. The tool handles people's source code, so a provable "nothing else leaves your machine" is part of the product, not an implementation detail.

## Consequences

Trusted publishing needs a public GitHub repo, a public package, a `repository.url` that exactly matches the repo, npm CLI 11.5.1 or newer, and Node 22.14 or newer in the release job. The trusted publisher is configured in the package's settings on npmjs.com, and the first successful publish must happen within 2 days of creating that configuration.
